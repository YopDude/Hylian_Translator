# Hylian Translator

Translate text into the **Hylian** scripts of *The Legend of Zelda* series, or read Hylian back into a real-world language with an on-screen Hylian keyboard.

Live site: https://yopdude.github.io/Hylian_Translator/ (custom domain: https://zeldatranslator.com)

## Features
- **Real world → Hylian:** English, Japanese (hiragana/katakana) and other European / Slavic / Korean input, converted to the Hylian scripts. Scripts: Ocarina of Time (3D and N64), Wind Waker, Twilight Princess (GameCube and mirrored Wii), Skyward Sword, Breath of the Wild, Gerudo, Sheikah, Mudoran.
- **Hylian → real world (⇆ swap):** tap Hylian keys, get the transliteration (sounds, not meanings) in the chosen language. English-alphabet scripts map letter by letter, kana-based scripts (Ocarina of Time, Wind Waker) syllable by syllable. Output: Latin languages as typed, Japanese as hiragana, Korean as hangul, Russian / Ukrainian / Serbian as Cyrillic. Chinese is not supported and Mudoran can't be reversed. Key labels follow the output language.
- **Customisation:** font colour (the output panel turns dark automatically if the colour is too light to read), font size, PNG export, alphabet chart per script.
- **14 languages**, each on its own static pages (`/`, `/ja/`, `/es/` ...) with `hreflang` and a sitemap.
- **Session memory:** `state.js` keeps the text, direction, script, colour, size and keyboard input in `localStorage`, so reloads and language switches pick up where you left off.
- **Temporary banner** that hides itself after a set date.

## Build
No dependencies, Node 16+:

    node build.js

Edit the templates / `i18n` files, rebuild, commit the generated pages. The cache-buster (`?v=…`) is a hash of the scripts and `vendor/` files, so it updates itself. `<lastmod>` in the sitemap is kept in `tools/lastmod.json` and only changes for pages whose content changed (commit that file too). The build also lists any font, chart, icon or favicon that the site uses but that is missing from the folder.

**Add a language:** add its block to `i18n/translations.js`, `i18n/extras.js` and `i18n/ui-strings.js`, add a line to `LANGS` in `build.js`, rebuild.

`images/icons/<version>.<ext>` (`ocarinaOfTime3d`, `ocarinaOfTime64`, `windwaker`, `twilightPrincess`, `skywardSword`, `botw`, `gerudo`, `sheikah`, `mudoran`). Square 96 px WebP images (they are shown at ~28 px). To use another format set `ICON_EXT` in `build.js` and rebuild.

## Offline support and installing as an app
`sw.js` and every `site.webmanifest` (one per language folder, so an app installed from `/ja/` opens the Japanese page) are **generated by `node build.js`**: edit `templates/sw.template.js` or the manifest block in `build.js`, never the generated files. The service worker saves the pages and the translator's files (about 2.5 MB) so the site works offline and is installable (`display: standalone`). Online nothing changes: pages are always checked against the server first, scripts/styles/fonts are cache-first because their URLs carry a `?v=` hash, and `dict/` (the 18 MB Japanese dictionary) is saved the first time it is downloaded in its own cache (`hylian-dict-v1`) that new builds never clear, so kanji conversion stays fast and also works offline. Each build creates a new cache named after the build hash and deletes the old one. Service workers need HTTPS (or localhost).

## Phones
- Tapping the forward-mode text box scrolls it to the top of the screen, so the translation just below it stays visible above the keyboard (`bringInputToTop` at the end of `script.js`).
- Hylian → real world: the Hylian input is sticky at the top while the keys are scrolled. `body` must not get `overflow: hidden/auto`, because that stops `position: sticky` from working.
- On a touch device (`window.HylianTouch.isPrimary()`) nothing focuses a text field by itself: tapping a Hylian key, the switch-direction button or the script dropdown does not open the phone's keyboard. Tapping the input does, and while it is focused the keys behave as on a computer.
- The keyboard has a **Hide phonetics** button (small letters under the keys, remembered in `localStorage`) and a tooltip on **Mirror text**; the strings are `kbHidePhonetics`, `kbShowPhonetics`, `kbPhoneticsTip` and `kbMirrorTip` in `i18n/ui-strings.js`.
- **Per-script size on phones:** the `size-adjust` in `@font-face` gives every script the same glyph height, but on a narrow screen the kana scripts look small and the wide letter scripts take many lines. `--font-scale` multipliers at the end of `styles.css` (phone width only, `#translatedText[data-hylian=...]`) even this out; the slider still sets `--out-size`. Change a number there to tune one script.
- **Hylian → real world keyboard:** the full message is remembered when a switch to a kana script drops letters (`masterMessage` in `reverse.js`), so flipping through scripts and back to an alphabet restores it; any edit forgets it.
- **Kanji dictionary for yourself:** open the site once with `?kanji=on` (any language) and that browser preloads the dictionary on every page, keeps it in the offline cache and asks for persistent storage; `?kanji=off` undoes it. The Japanese homepage always preloads it.
- Chart images carry `?v=<hash of images/*.webp>` (`imgVer`), so replacing a chart reaches visitors who already cached it.
- The short intro paragraph under the translator is `introText` in `i18n/extras.js` (one per language).

## Images
Keep images small: charts are WebP (≈30–250 KB each, max 1800 px wide, 1200 px for the mobile versions), icons 96 px WebP. Only the social-preview images (`Hylian_Translator_*.png`) stay PNG, because social sites don't reliably read WebP. The chart is only downloaded when someone hovers/taps the eye button.

## Fonts
- `RocknRollOne` and `ReggaeOne` (the UI fonts) are split by character range, so an English page loads about 85 KB of them instead of 2 MB: `*-Latin.subset.woff2` for Latin text, `*-JPLabels.subset.woff2` (a few KB) for the language names shown on every page, and `*-JP.subset.woff2` (kana + the kanji used on the ja pages) only where Japanese text really appears. Regenerate with `python3 tools/subset-fonts.py RocknRollOne ReggaeOne` after adding kanji to the Japanese text. `node build.js` warns if a non-Japanese page would pull in the big Japanese file. Both fonts are SIL OFL 1.1 (`fonts/OFL-*.txt`).
- The Hylian game fonts use `font-display: block` and are fetched in the background once the page is idle (~45 KB in total), and the keyboard hides its glyphs until the selected font is ready, so switching script never flashes the plain mapping characters. `window.HylianFonts` (in `script.js`) is the helper for this.
- `tools/normalize-font-metrics.py` gives every Hylian font the same vertical metrics (outlines untouched) so switching scripts doesn't resize the output box.
- `tools/subset-fonts.py` rebuilds the Chinese/Korean UI fonts (Noto Sans) and the Japanese/Chinese/Korean/Cyrillic title fonts (Noto Serif, Forum) from the text of the built pages. Run `node build.js` first; re-run it after adding characters to those languages. Licences: `fonts/NotoSansSC-OFL.txt` (all Noto CJK fonts) and `fonts/OFL-Forum.txt`.
- `styles.css` also carries `ascent-override` / `descent-override` per Hylian font (written by the same tool), so the key and output spacing stays correct even if a browser or a copied folder still has an old font file.
- After changing any font file, bump `FONT_VER` in `build.js` so browsers re-download it (it versions every font URL).

## Banner
Set in `BANNER` in `build.js` (id, start and end date). It is on every page but hides itself after `end` and can be dismissed. `BANNER = null` removes it.

## Hidden text
The scope note under the Hylian keyboard ("Transliteration only…") is kept in the page but hidden: remove the `hidden` attribute on `.rev-note` in `templates/index.template.html` to show it.
